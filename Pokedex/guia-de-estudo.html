Resumo de 1 minuto

Se você só tiver tempo para isto, decore estes pontos:

  • Todos os projetos são React + Vite, com a mesma organização de pastas: components, pages, hooks, services, config, utils.
  • Os hooks que mais aparecem: useState (333 vezes), useEffect (165), useRef (122), useCallback (85) e useMemo (67).
  • Muitos projetos são versões em React de projetos Spring Boot. A ideia é sempre a mesma: o que o servidor fazia, agora o navegador faz.
  • Variável que começa com VITE_ vai para o navegador e qualquer um pode ver. Chave secreta nunca tem VITE_: ela fica na pasta api/ (Vercel Functions).
  • Busca de dados: fetch dentro de useEffect, com estados loading / sucesso / erro e uma função de limpeza (cleanup).
  • Rotas: BrowserRouter + Routes + Route; parâmetros com useParams; rota protegida com <Navigate>.
  • Banco sem back-end: Supabase com chave publicável, protegido por RLS.

Vite e estrutura do projeto

O Vite cria e roda o projeto. Os comandos que aparecem em todos os READMEs:

npm create vite@latest meu-app   # cria (escolha React + JavaScript)
npm install                      # instala as dependências do package.json
npm run dev                      # roda em http://localhost:5173
npm run build                    # gera a pasta dist/ para publicar
npm run preview                  # testa o build localmente

Como o app começa (main.jsx)

import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import App from "./App.jsx";

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <App />
  </StrictMode>
);

O index.html tem uma <div id="root">. O React desenha o <App /> dentro dela.

Pegadinha do StrictMode: no npm run dev, ele roda cada useEffect duas vezes de propósito, para achar bugs. Em produção roda uma vez. O AraUrlShortener guarda a Promise num Map para não contar dois cliques no link.

Componentes, JSX e props

Um componente é uma função que devolve JSX (HTML dentro do JavaScript). O nome começa com letra maiúscula. Ele recebe dados do pai por props, que são só leitura.

// Pai passa dados por props
<PokemonCard pokemon={p} isFavorite={true} onOpen={abrir} />

// Filho recebe com desestruturação
export default function PokemonCard({ pokemon, isFavorite, onOpen }) {
  return (
    <li className="card" onClick={() => onOpen(pokemon.id)}>
      {pokemon.name} {isFavorite && "★"}
    </li>
  );
}
  • No JSX é className, não class. Expressões JS vão entre { }.
  • Condicional: {cond && <X/>} ou {cond ? <A/> : <B/>}.
  • children: o que fica entre as tags. Usado no PageLayout e no ProtectedRoute: <ProtectedRoute><Home/></ProtectedRoute>.
  • O filho avisa o pai chamando uma função recebida por props (onOpen, onToggleFavorite). Os dados descem, os eventos sobem.

Hooks

Regra: hooks só podem ser chamados no topo do componente (nunca dentro de if ou loop) e só em componentes ou outros hooks.

useState: guardar um valor que muda a tela

const [busca, setBusca] = useState("");
setBusca("pikachu");                         // re-renderiza
setOrdem(atual => ({ ...atual, direcao: "desc" })); // forma com função: usa o valor anterior

Nunca altere o estado direto (busca = "x" ou lista.push()). Sempre use o set com um valor novo (por isso o ...spread).

useEffect: efeitos colaterais (fetch, timers, eventos)

useEffect(() => {
  const timer = setTimeout(() => setDebounced(value), delay);
  return () => clearTimeout(timer);   // cleanup: roda antes do próximo efeito e ao desmontar
}, [value, delay]);                   // dependências

[] vazio

Roda uma vez, quando o componente aparece.

[a, b]

Roda de novo sempre que a ou b mudar.

Sem array

Roda depois de toda renderização.

return () => {}

Limpeza: cancela timer, fetch (AbortController) ou removeEventListener.

useRef: valor que NÃO re-renderiza

Dois usos nos projetos: (1) pegar um elemento do DOM, (2) guardar algo entre renderizações sem redesenhar a tela.

const containerRef = useRef(null);
<div ref={containerRef} />            // MapBoxAPI: o mapa é criado dentro desta div
const abortRef = useRef(null);
abortRef.current?.abort();            // cancela a busca anterior

useMemo e useCallback: evitar recálculo

// useMemo guarda um VALOR calculado (Pokedex: lista filtrada é estado derivado)
const resultado = useMemo(
  () => sortPokemon(filterPokemon(lista, { busca, tipo }), ordem),
  [lista, busca, tipo, ordem]
);
// useCallback guarda uma FUNÇÃO (não é recriada a cada render)
const limpar = useCallback(() => { setBusca(""); setTipo(null); }, []);
Estado derivado: a lista filtrada não vai num useState. Ela é calculada a partir da lista base + filtros. É o padrão do usePokedexFilters.

Hooks customizados

Uma função que começa com use e usa outros hooks. Serve para reaproveitar lógica. Exemplos da pasta: useTheme, useDebouncedValue, useRequest, useGitHub, useFavoritos, usePokedexFilters, useFiltrosDaUrl.

Listas, eventos e formulários

Listas com map e key

{pokemons.map((pokemon) => (
  <PokemonCard key={pokemon.id} pokemon={pokemon} />
))}

A key precisa ser única e estável (o id). Ela diz ao React qual item é qual quando a lista muda. Evite usar o índice do array. Para filtrar, use .filter() antes do .map().

Eventos e formulário controlado

const [url, setUrl] = useState("");

function handleSubmit(e) {
  e.preventDefault();          // impede a página de recarregar
  encurtar(url);
}

<form onSubmit={handleSubmit}>
  <input value={url} onChange={(e) => setUrl(e.target.value)} />
  <button type="submit">Encurtar</button>
</form>

"Controlado" quer dizer que o valor do input vem do estado (value) e cada tecla atualiza o estado (onChange). Eventos em camelCase: onClick, onChange, onSubmit. Passe a função, não chame: onClick={abrir} e não onClick={abrir()}.

localStorage e sessionStorage

localStorage.setItem("tema", JSON.stringify(valor));
const salvo = JSON.parse(localStorage.getItem("tema"));

localStorage fica para sempre; sessionStorage some ao fechar a aba (usado na sessão de login). Só guarda texto, por isso o JSON.stringify. Os projetos colocam em try/catch porque pode falhar em aba anônima.

Consumindo APIs

O padrão básico, igual ao useGitHub:

const [state, setState] = useState({ status: "loading", data: null, error: null });

useEffect(() => {
  let active = true;
  setState({ status: "loading", data: null, error: null });

  fetcher(username)
    .then((data) => active && setState({ status: "ready", data, error: null }))
    .catch((error) => active && setState({ status: "error", data: null, error }));

  return () => { active = false; };   // ignora resposta antiga
}, [fetcher, username]);

Com async/await:

async function buscar() {
  const response = await fetch(url);
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  return await response.json();
}
Pegadinha clássica: o fetch só dá erro (cai no catch) se não houver rede. Um 404 ou 500 chega "normal". Por isso sempre confira response.ok.

Regra de ouro: tudo com prefixo VITE_ é embutido no JavaScript do site, e qualquer visitante consegue ler. Token do GitHub, Spotify, Gemini, Stripe (secret) e WakaTime ficam sem VITE_, na pasta api/.

Como a pasta api/ funciona

O navegador chama /api/github no próprio site. Quem chama o GitHub com o token é o servidor:

  • Em produção: a Vercel transforma api/github.js numa Vercel Function (serverless).
  • No npm run dev: o vite.config.js registra um middleware que atende a mesma rota.
  • Arquivo que começa com _ (ex.: _github.js) não vira rota; guarda a lógica compartilhada.

Projetos com api/: GitHubAPI, ContributorStats, SpotifyAPI, GeminiAPI, StripeAPI, StripeAPI_2, WakaTimeAPI, CanvasAPI, Captcha_React, SubtitlesGenerator.

Captcha: validar só no front não protege nada, porque um robô chama sua API direto. A secret key valida no servidor (api/).

<BrowserRouter><App /></BrowserRouter>

  <Route path="/" element={<Navigate to="/login" replace />} />
  <Route path="/login" element={<Login />} />

Context API (SecureLoginPUC_React)

Context compartilha um dado com todos os componentes, sem passar props de pai em filho ("prop drilling"). Usado para o usuário logado.

// 1. Criar
export const AuthContext = createContext({ usuario: null, login: async () => false, logout: () => {} });
export const useAuth = () => useContext(AuthContext);

// 2. Prover (envolve o App)
export default function AuthProvider({ children }) {
  const [usuario, setUsuario] = useState(readStoredSession);
  const value = useMemo(() => ({ usuario, login, logout }), [usuario, login, logout]);
  return <AuthContext.Provider value={value}>{children}</AuthContext.Provider>;
}

// 3. Usar em qualquer lugar
const ProtectedRoute = ({ children }) => {
  const { usuario } = useAuth();
  return usuario ? children : <Navigate to="/login" replace />;
};

Nesse projeto não há back-end: os usuários ficam no localStorage (senha com hash), a sessão no sessionStorage, o e-mail de recuperação sai pelo EmailJS e o login tem reCAPTCHA.

Supabase (Pokedex, AraUrlShortener, RadioBrowser)

Banco PostgreSQL na nuvem que o navegador acessa por HTTPS, sem servidor próprio.

import { createClient } from "@supabase/supabase-js";
export const supabase = createClient(
  import.meta.env.VITE_SUPABASE_URL,
  import.meta.env.VITE_SUPABASE_PUBLISHABLE_KEY
);

// repository
await supabase.from("favorites").insert({ pokemon_id: 25 });
await supabase.from("favorites").select("*");
await supabase.rpc("resolve_url", { p_short_url: code });   // chama função SQL
  • Por que a chave pode ir para o navegador? A chave publicável (anon) não dá poder sozinha. Quem protege as tabelas é o RLS (Row Level Security): regras no banco dizendo quem pode ler e escrever.
  • A service_role / secret key nunca vai no front.
  • Comparação com Spring: lá era JDBC + Spring Data JPA no servidor; aqui o SDK supabase-js chama a Data API.
  • Camadas: componente → service (regras) → repository (banco).

Perguntas de revisão

Tente responder antes de abrir.

Qual a diferença entre props e state?
Props vêm do componente pai e são só leitura. State é do próprio componente, muda com o set e faz a tela re-renderizar.
Para que serve o array de dependências do useEffect?
Diz quando o efeito roda de novo. [] roda uma vez ao montar; [x] roda quando x muda; sem array roda em toda renderização.
O que é a função de cleanup do useEffect e quando ela roda?
É a função retornada pelo efeito. Roda antes do efeito rodar de novo e quando o componente sai da tela. Serve para cancelar timer, fetch (abort()) e remover event listeners.
Qual a diferença entre useRef e useState?
Mudar ref.current não re-renderiza a tela; mudar o state re-renderiza. useRef serve para acessar elementos do DOM ou guardar valores entre renderizações.
useMemo x useCallback?
useMemo memoriza um valor calculado (ex.: lista filtrada). useCallback memoriza uma função. Os dois só recalculam quando as dependências mudam.
Por que a prop key é obrigatória em listas?
Para o React identificar cada item entre renderizações e atualizar só o que mudou. Deve ser única e estável, como o id.
Por que usar e.preventDefault() no onSubmit?
O comportamento padrão do form é recarregar a página. preventDefault impede isso para o React tratar o envio.
Por que o fetch não cai no catch com erro 404?
O fetch só rejeita a Promise em falha de rede. Respostas HTTP de erro chegam normalmente; é preciso checar response.ok ou response.status.
O que é debounce e por que usar?
Esperar o usuário parar de digitar (ex.: 400 ms) antes de buscar. Evita uma requisição por tecla.
O que é condição de corrida (race condition) num fetch e como resolver?
Uma resposta antiga chega depois da nova e mostra o dado errado. Resolve cancelando a requisição anterior com AbortController no cleanup (ou ignorando com uma flag active).
Qual o perigo de uma variável com prefixo VITE_?
Ela é embutida no código do navegador e qualquer pessoa pode ler. Nunca coloque segredos nela. Segredos ficam no servidor (pasta api/, Vercel Functions), lidos com process.env.
Como ler uma variável de ambiente no React com Vite?
import.meta.env.VITE_NOME, definida no arquivo .env.local.
Por que a chave publicável do Supabase pode ficar no navegador?
Porque a segurança está no RLS (Row Level Security) e nas funções SQL do banco, não na chave. A secret / service_role nunca vai para o front.
Como pegar o parâmetro de uma rota /:shortUrl?
const {"{"} shortUrl {"}"} = useParams(); do react-router-dom.
Como fazer uma rota protegida?
Um componente que lê o usuário (via Context) e devolve children se estiver logado, ou <Navigate to="/login" replace /> se não.
Para que serve o Context API?
Compartilhar dados globais (usuário logado, tema, idioma) com qualquer componente sem passar props por todos os níveis. Passos: createContext, <Provider value>, useContext.
Por que o vercel.json tem um rewrite para /index.html?
Numa SPA, só existe o index.html. Sem o rewrite, abrir /home direto ou dar F5 numa rota dá 404. O rewrite entrega o index.html e o React Router mostra a tela certa.
Por que o efeito roda duas vezes no npm run dev?
Por causa do <StrictMode>, que faz isso de propósito em desenvolvimento para revelar efeitos sem cleanup. Em produção roda uma vez.
O que mudou dos projetos Spring Boot para os React?
O trabalho saiu do servidor para o navegador: o Thymeleaf montava o HTML, agora o React desenha; JDBC/JPA virou Supabase pelo SDK; Controller virou rota do React Router; Service e Repository continuam como arquivos JS.
Por que validar captcha no front não basta?
Um robô pode chamar a API direto, sem passar pela tela. A validação de verdade é no servidor, com a secret key.
